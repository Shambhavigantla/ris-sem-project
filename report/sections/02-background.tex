\section{Literature Review and Preliminaries}
\label{sec:background}

\subsection{Related work}

\paragraph{Searchable encryption.} Song, Wagner and Perrig gave the first practical scheme for searching
encrypted data~\cite{song2000practical}. Curtmola et al.\ defined the security of searchable symmetric
encryption and built schemes with an encrypted index~\cite{curtmola2006sse}. Other work added conjunctive and
other richer queries~\cite{ballard2005conjunctive}. All of these assume that the user holds a long secret key.

\paragraph{Keys from passwords.} Password-protected secret sharing (PPSS) lets a user recover a secret from a
password and a threshold of servers~\cite{bagherzandi2011pps}. Jarecki et al.\ made it round-optimal and then
built it from a threshold oblivious pseudorandom function (OPRF)~\cite{jarecki2014round,jarecki2016highly,
jarecki2017toppss}. DPaSE derives many keys from one password~\cite{das2022dpase}. Password-authenticated keyword
search and PASE apply the same idea to searchable encryption~\cite{huang2017paks,chen2021pase}. All of these rely
on groups where the discrete logarithm is hard, which a quantum computer breaks~\cite{shor1994}.

\paragraph{Quantum resistance.} Roy et al.\ built PPSS from lattices~\cite{roy2021pps}. Jiang et al.\ built a
lattice threshold single-sign-on scheme with updatable server keys~\cite{jiang2022sso} and a password-protected
outsourcing scheme, QPause~\cite{jiang2024qpause}. QPASE adds keyword search, which gives the first
password-authenticated searchable encryption scheme that resists quantum attacks~\cite{jiang2024qpase}.

\subsection{Ring learning with errors}

All lattice operations in QPASE take place in $\Rq$. An element is a polynomial of degree below $n$ with
coefficients in $\mathbb{Z}_q$, and a product wraps around with $X^n = -1$. Security rests on the decision
learning-with-errors problem~\cite{regev2009lwe} in its ring form~\cite{lyubashevsky2010ring}.

\begin{definition}[Decision ring-LWE]
For a secret $s \leftarrow \chi_\sigma$, samples $(a, a s + e)$ with $a$ uniform in $\Rq$ and
$e \leftarrow \chi_\sigma$ are computationally indistinguishable from pairs $(a, b)$ with $b$ uniform in $\Rq$.
\end{definition}

\subsection{Lattice pseudorandom function}

QPASE uses the Banerjee--Peikert pseudorandom function (PRF)~\cite{banerjee2014prf}. The gadget vector
$G = (1, 2, \dots, 2^{\ell-1})$ and its inverse $G^{-1}$, the bit decomposition of each coefficient, turn a vector
in $\Rq^{1\times\ell}$ into an $\ell \times \ell$ matrix of binary polynomials with $G \cdot G^{-1}(v) = v$. For an
input $x = (x_1, \dots, x_L) \in \{0,1\}^L$ and the public vectors $a_0, a_1$,
\begin{equation}
a_x = a_{x_1} \, G^{-1}\!\big(a_{x_2} \, G^{-1}( \cdots G^{-1}(a_{x_L}))\big),
\qquad F_k(x) = \big\lfloor (p/q) \cdot a_x \cdot k \big\rceil .
\label{eq:bp-prf}
\end{equation}
Computing $a_x$ takes $L-1$ steps, each a product of a $1 \times \ell$ vector with an $\ell \times \ell$ matrix of
ring elements. The rounding to $\mathbb{Z}_p$ is the learning-with-rounding idea~\cite{alwen2013lwr}. We call one
evaluation of $a_x$ a \emph{PRF chain}. \Cref{sec:evaluation-qpase} shows that this chain dominates the cost of the
whole scheme.

\subsection{Threshold OPRF with a robust extractor}

The TOPRF lets the user evaluate $F_K(x)$ on its password encoding $x$ under the master key $K$, which no single
party holds~\cite{albrecht2021oprf,jiang2022sso}. Server $S_i$ holds a share $k_i$ of $K$ and publishes
$pk_i = a k_i + 2e_i$. The protocol has three moves.
\begin{enumerate}
  \item \textbf{Blind.} The user samples $r, e \leftarrow \chi_\sigma$ and sends $b = a r + a_x + 2e$ to at
        least $t$ servers. The term $a r + 2e$ hides $a_x$, and therefore the password.
  \item \textbf{Evaluate.} Each contacted server returns $b_{k_i} = b k_i + 2e'_i$.
  \item \textbf{Combine.} With the Lagrange coefficients $\lambda_i$ of the contacted servers, the user computes
        \begin{equation}
        F = \sum_i \lambda_i b_{k_i} - r \sum_i \lambda_i pk_i = a_x K + 2e'' .
        \label{eq:toprf-combine}
        \end{equation}
\end{enumerate}
The paper's Fig.~2 rounds $b$, $b_{k_i}$ and the public key $pk_i$ (written $vk_i$ there) to $\mathbb{Z}_p$; we
send them unrounded, as its Fig.~1 does
(\cref{sec:decisions}). The noise $2e''$ is even and small, but it changes from one login to the next, so rounding $F$ alone would give a
slightly different key each time. QPASE removes it with the robust extractor of Ding et al.~\cite{ding2012kex}.
For a coefficient $c$ in its centred representation, two signal functions mark whether $c$ lies near the
boundary between the two halves of $\mathbb{Z}_q$:
\[
\sigma_0(c) = \begin{cases} 0 & c \in [-\lfloor q/4 \rfloor, \lfloor q/4 \rfloor] \\ 1 & \text{otherwise} \end{cases},
\qquad
\sigma_1(c) = \begin{cases} 0 & c \in [-\lfloor q/4 \rfloor + 1, \lfloor q/4 \rfloor + 1] \\ 1 & \text{otherwise.} \end{cases}
\]
The hint algorithm $S(y)$ outputs $\sigma_b(y)$ for a random bit $b$, and the extractor is
$E(x, \sigma) = \big((x + \sigma \cdot \tfrac{q-1}{2}) \bmod q\big) \bmod 2$, in Ding et al.'s form; the paper
prints a slightly different one (\cref{sec:decisions}). If $x - y$ is even and small, then
$E(x, S(y)) = E(y, S(y))$. The user key is $\Ku = E(F, \sigma)$, one bit per coefficient.

\subsection{Distributed key generation}

The servers create the master key $K$ without a trusted dealer~\cite{bendlin2013share}. Each server $S_i$ deals a
Shamir sharing of a random contribution $s_i$ to all servers, and server $S_j$ sums the shares it receives to get
$k_j$. The master key $K = \sum_i s_i$ is never assembled anywhere. The paper's Definition~11 shares with
polynomials of degree $t$, so $t + 1$ servers can use $K$ through their shares and $t$ learn nothing about it. We
share with degree $t - 1$, so that the $t$ servers of a Login suffice (\cref{sec:decisions}).

\subsection{Symmetric and signature primitives}

\paragraph{HKDF and PRF.} QPASE derives a search key per keyword with an extract-then-expand key derivation
function, $\dsk = \mathrm{HKDF}(\Ku, w)$~\cite{krawczyk2010hkdf}, and tags each document with
$v = \mathrm{PRF}(\dsk, \rho)$ for a random $\rho$.

\paragraph{Signatures.} The user signs its Login proof and every Outsource and Retrieve request, and the servers
sign their key-update shares, with CRYSTALS-Dilithium~\cite{bai2021dilithium},
standardised by NIST as ML-DSA~\cite{fips204}. The user's key pair is derived from $\Ku$, so it is never stored.

\paragraph{Symmetric encryption.} Documents and index entries are encrypted with AES-256. Grover's algorithm
halves its effective key length~\cite{grover1996}, which still leaves 128 bits of security. We use the
authenticated Galois/Counter Mode~\cite{dworkin2007gcm}.
