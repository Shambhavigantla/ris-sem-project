\section{Comparative Study}
\label{sec:comparison}

\Cref{tab:qpase-vs-ci} compares the paper's search with the counter index, using our measurements. The counter
index wins on the server side: the key stays on the device, it is forward private, and its rows are smaller. It
pays with a second round trip and a counter table to store and upload. The user's cost is the same.

\Cref{tab:related} summarises the paper's Table~V, which compares QPASE with earlier password-based
schemes~\cite{jiang2024qpase}. QPASE is the only one that is both quantum resistant and supports data retrieval.
The overhead column counts only exponentiations $T_{exe}$, so the lattice schemes read $0 / 0$. That does not mean
they are cheap: in our implementation one lattice PRF chain takes \AxMedian. The counter index keeps every property
in QPASE's row and adds forward privacy, which the table does not compare.
