\section{Introduction}
\label{sec:introduction}

Users keep sensitive data with cloud providers: medical records, invoices, travel bookings. Encrypting files before
upload protects them, but the server can no longer search them. Searchable symmetric encryption (SSE) closes this
gap: the user attaches an encrypted index to each file, and the server finds the files that match a keyword without
learning the keyword or the contents~\cite{song2000practical,curtmola2006sse}.

SSE needs a long random key on every device the user searches from, and every copy is one more place it can leak.
Password-protected secret sharing lets a user recover a strong key from a password with the help of several
servers~\cite{jarecki2016highly}, and PASE combines this idea with searchable encryption~\cite{chen2021pase}. These
schemes rest on the discrete logarithm, which a quantum computer breaks~\cite{shor1994}. QPASE is the first PASE
scheme built on lattices~\cite{jiang2024qpase}: a threshold of $t$ out of $N$ servers turns the user's password into
a user key $\Ku$, and every other key is derived from $\Ku$.

The paper does not publish its implementation. This project asks three questions. Can QPASE be built from the paper
alone? What does it cost, and does its design hold up when each step runs? And can search keep the key on the
user's device and touch only the matching files?

\paragraph{Contributions.}
\begin{itemize}
  \item \textbf{A working QPASE} in Python covering every phase of the paper, with eight notebooks and \UnitTests{}
        unit tests, and a record of each gap in the paper (\cref{sec:qpase,sec:implementation}).
  \item \textbf{Measured costs} of every phase on one machine, explained by the count of lattice PRF evaluations
        and compared with the paper (\cref{sec:evaluation-qpase}).
  \item \textbf{Two security findings}: offline password guessing at PARAM~II in the ring we use, and key-update
        commitments that reveal the shares (\cref{sec:findings}).
  \item \textbf{A counter-based search index} with forward privacy and a much faster server-side search
        (\cref{sec:counter-index,sec:counter-analysis,sec:counter-evaluation,sec:comparison}).
\end{itemize}
